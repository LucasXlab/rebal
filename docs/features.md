## 一、数据从哪来

### 行情（价格）

| `quotes.provider` | 说明 |
|---|---|
| `tencent`（默认） | 腾讯公开行情接口，支持 A 股、港股、美股，一次请求可查多只；返回 GBK，代码按 GBK 解码 |
| `csv` | 你自己维护一个价格文件（`quotes.price_file`），完全不联网 |
| `mock` | 内置示例数据（`fixtures/quotes.mock.json`），`init --demo` 用它 |

`quote_id` 是行情源里的代码，**前缀决定市场**：`us` 美股（`usVTI`）、`sh` 沪市（`sh510300`）、
`sz` 深市（`sz159915`）、`hk` 港股（`hk00700`）。不填则用证券代码本身。

程序会校验"`quote_id` 前缀推出的币种"与 `assets.*.currency` 是否一致——不一致直接报
`quote_invalid` 退出，而不是按错误汇率算出一张看起来正常的订单。

### 汇率

| `fx.provider` | 说明 |
|---|---|
| `frankfurter`（默认） | ECB 日参考价，工作日更新，周末与节假日沿用上一交易日；**不是实时汇率** |
| `static` | 在 `[fx.static]` 里写死（`USD = 7.0`），完全离线、结果可复现 |
| `mock` | 内置示例汇率 |

`rates[X]` 的含义是"1 单位本币等于多少 X"，程序内部换算成 `1 X = ? 本币` 再用。

### 自报价（`provider = "csv"`）

价格文件表头必须是 `symbol,price,currency,as_of`：

```csv
symbol,price,currency,as_of
VTI,300.00,USD,2026-10-29
510300,4.00,CNY,2026-10-29
```

适合：你的市场不在腾讯覆盖范围内、你想用收盘价而不是盘中价、或者你在核对历史数据。

## 二、持仓 CSV

```csv
symbol,quantity,account,currency,price,name
VTI,10,ibkr,,,
BND,50,ibkr,,,
510300,1000,futu,,,
```

- **必填**：`symbol`、`quantity`。
- **可选**：`account`（默认 `default`；单账户时输出里不显示账户表）、
  `currency`（不填用 `[assets.X].currency`）、
  `price`（填了就用这个价，**不联网**；留空则按 `quotes.provider` 取价）、
  `name`（仅用于显示）。
- 列名可以在 `[holdings]` 里改（`symbol_column = "代码"` 之类），方便直接用券商导出的文件。
- 同一 `symbol` 出现在多行会合并；若两行 `currency` 不同则报 `currency_conflict`（不会猜）。
- 上限：文件 ≤ 5 MB、数据行 ≤ 5000。

**数量写成 0 的行会被保留但不产生订单**——清仓后建议直接删掉那行。

## 三、`status`：我现在偏多少

```
$ rebal status
我的组合 · 本币 CNY · 总市值 ¥53,046.42
行情 2026-10-29 23:10（腾讯行情） · 汇率 2026-10-29 23:10（Frankfurter）

资产类别        市值   目标   当前     偏离   带宽  状态
────────────────────────────────────────────────────────
美股      ¥25,197.52  50.0%  47.5%   -2.5pp  3.0pp  正常
A股        ¥4,073.00  20.0%   7.7%  -12.3pp  3.0pp  越界
债券      ¥23,775.90  30.0%  44.8%  +14.8pp  3.0pp  越界
```

- **偏离** = 当前市值 − 目标市值，再除以"本次投入后的总市值"。正数是超配，负数是欠配。
- **带宽**：`[bands]` 里配的容忍度，`0.03` = 3 个百分点。`|偏离| > 带宽` 才算越界。
- `--strict`：有类别越界时退出码 4（方便放进定时任务里判断），否则仍为 0。
- 只有一个账户时，账户表不打印（没有信息量）。

## 四、`plan`：这笔钱怎么买

```
$ rebal plan --cash 6000
我的组合 · 本币 CNY · 总市值 ¥53,046.42
本次投入 ¥6,000.00 · 价格来自 腾讯行情

方向  代码    名称        类别   股数    价格       金额  手续费
────────────────────────────────────────────────────────────────
买入  510300  沪深300ETF  A股   1,400  ¥4.073  ¥5,702.20   ¥0.00

合计 1 笔 · 买入 ¥5,702.20 · 手续费 ¥0.00 · 剩余现金 ¥297.80
执行后  美股 -7.3pp · A股 -3.4pp · 债券 +10.3pp

警告
  美股 还差 7.3pp，但一手 1 股约 ¥2,519.75，现金只剩 ¥297.80，买不起
  A股 还差 3.4pp，但一手 100 股约 ¥407.30，现金只剩 ¥297.80，买不起
  债券 超配 10.3pp，本次不卖出；加 --sell 可以配平
```

### 现金从哪来

`--cash <金额>`，或配置里的 `[contribution] amount`。两者都没有 → 退出码 2 `cash_required`。

### 为什么只买了一笔

算法是**逐手买入**：每次挑"缺得最多"的类别买一手，买完重新比较。所以：

- 现金不够买一手时停下，并在 `警告` 里说清"一手多少钱、你只剩多少"；
- `max_orders` 到了就停，剩下的类别记 `max_orders_reached`；
- 整笔低于 `min_trade_value` 的买单会被丢掉（避免"买 30 块"这种噪音）。

### 卖出（`--sell`）

默认**不卖**（`policy.allow_sell = false`）。加 `--sell` 才会在类别超出带宽时卖出，
卖出净额进入本次可用现金再买。反向用 `--no-sell` 可以临时覆盖"配置里允许卖"的情况。

**卖出可能产生税务事件**，这一步请自己判断。

### 计划文件

保存到 `.rebal/plans/<planId>.json` 与 `latest.json`，只保留最近 52 份。
`--no-save` 只算不存。`planId` 是本地时间（`2026-10-29T19-54-19-04-00`），同秒重复生成会加 `-2`。

### 没有可执行的订单时

已经配平、或者现金不够买任何一手 → 退出码 **4**（`no_actionable_orders`），
仍然输出完整的 Plan（`--json` 里也一样），方便脚本判断。

## 五、`check`：上期计划执行了没有

它**读 `holdings.csv` 里的股数**跟你上次的计划比，所以成交后要**先手动更新 `holdings.csv`**。

```
$ rebal check
核对计划 2026-10-29T19-54-19-04-00
创建于 2026-10-29 19:54 · 实际持仓来自 holdings.csv

代码    方向  计划(股)  实际(股)  状态
──────────────────────────────────────
510300  买入     1,400     1,400  完成
```

| 状态 | 含义 |
|---|---|
| 完成 | 实际变动量 ≥ 计划量（反向或超量另有状态） |
| 部分 | 实际变动量 > 0 但小于计划量 |
| 未执行 | 实际变动量为 0 |
| 超量 | 实际变动量明显超过计划量 |
| 反向 | 实际方向与计划相反 |

"计划外变动"：持仓里出现了计划里没有的股票变动。

`--plan <id|latest>` 指定核对哪一份；`--strict` 在没全完成时退出码 4。

## 六、`prices`：取到了什么

```
$ rebal prices
代码    行情里的名称               价格  货币  来源      获取时间          状态
───────────────────────────────────────────────────────────────────────────────
VTI     美国全股市ETF-Vanguard  $378.24  USD   腾讯行情  2026-10-30 01:10  新
BND     美国全债市ETF-Vanguard   $71.38  USD   腾讯行情  2026-10-30 01:10  新
510300  沪深300ETF华泰柏瑞       ¥4.118  CNY   腾讯行情  2026-10-30 01:10  新
```

**"行情里的名称"这一列是给核对用的**：`quote_id` 写错一个字母可能命中另一个真实标的
（例如 `usVTI` → `usVTIQ`），程序无法判断你的意图，但你可以一眼看出名称不对。

`--refresh` 强制忽略缓存重新取；`--offline` 只用缓存。

## 七、缓存与离线

- 价格按 `quotes.ttl_minutes`（默认 720 = 12 小时）缓存到 `.rebal/cache.json`；
  汇率同样缓存。缓存只影响"取价"，不影响任何计算规则。
- 用缓存时，来源列会标 `（缓存）`，并在 `警告` 里给出缓存时间。
- `--offline`：完全不联网。`tencent` / `frankfurter` 走缓存，缓存没有就报错退出；
  `csv` / `mock` / `static` 本来就离线，不受影响。
- 缓存文件可以随时删，下次运行会重建。

## 八、手续费、最小交易额与订单上限

```toml
[fees]
per_order = 0          # 每笔订单的手续费（本币）

[policy]
min_trade_value = 100  # 低于这个金额（本币）的订单不下
max_orders = 20        # 一次最多几笔
allow_sell = false     # 默认不卖
```

- 手续费**按笔**收（买一笔、卖一笔各记一次），会从可用现金里扣，并体现在"剩余现金"里。
- `min_trade_value` 丢掉的是"整笔金额"，不是"每手金额"。
- `max_orders` 同时约束卖单与买单的总数。

## 九、`--json`

所有命令都支持，输出一个对象（不带任何 ANSI 与装饰）。`plan` 的结构（节选）：

```json
{
  "schemaVersion": 1,
  "planId": "2026-10-29T19-54-19-04-00",
  "baseCurrency": "CNY",
  "cash": 6000,
  "orders": [
    {
      "symbol": "510300",
      "side": "buy",
      "classId": "cn_equity",
      "quantity": 900,
      "lotSize": 100,
      "unitPrice": 4,
      "currency": "CNY",
      "fxRate": 1,
      "value": 3600,
      "valueBase": 3600,
      "feeBase": 1.5
    }
  ],
  "skipped": [{ "classId": "us_equity", "reason": "lot_too_expensive" }],
  "warnings": ["…"],
  "remainingCash": 297,
  "feesTotal": 3,
  "before": { "totalBase": 49500, "classes": ["…"] },
  "after": { "totalBase": 55497, "maxAbsDriftPp": 14.15, "classes": ["…"] }
}
```

退出码仍然是主要信号：`4` 表示"跑通了但没有可执行订单"，此时 `--json` 里会多一个
`"code": "no_actionable_orders"`。错误对象只在退出码 1/2/3 时出现。

## 十、出错时怎么办

错误输出固定三行：

```
rebal: error: 一句话说清哪里错了 [机器码]
  出错位置: 具体细节
  怎么办：可以照着执行的下一步
```

- **退出码 2**：你的配置或命令有问题（改配置/改参数）。
- **退出码 3**：外部数据取不到（网络、行情源、汇率）。
- **退出码 4**：跑通了，但没有可执行的结果（不是错误）。
- **退出码 1**：程序缺陷。会打 stack，并写进错误日志；请带上 `--verbose` 的输出提 issue。

错误日志在 `.rebal/last-error.log`（JSONL，保留最近 20 条，单条 ≤ 8 KB）；
该目录不可写时会退回系统临时目录，并在错误块末尾打印实际路径。
