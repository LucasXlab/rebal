# 参照仓库的可照搬做法（inkdove）

参照仓库：https://github.com/Bowen1314/inkdove，克隆于 `reference/inkdove`（已在 `.gitignore` 里）。
只学做法，不学业务，不抄代码。每个阶段开工前重读本文件。

阅读顺序（2026-10-29）：README.md → SPEC.md → SPEC-phase2.md「测试要求」→ DESIGN.md 第 0–2 节 →
docs/deviations.md 前 20 条 → docs/external-apis.md 前 45 行 → docs/development.md →
server/test/{auth,abuse,helpers}.js → `git log --format='%s'` 前 60 条。

下面的每一条都注明出处，并写清本项目怎么用。

1. **SPEC 是唯一契约，字段名和枚举值精确到一字不差；有歧义按"最简单、能跑通"处理，并记进偏离文档。**
   出处：`SPEC.md` 第 8 行（"本文件是唯一契约：路由、字段名、枚举值必须一字不差……有歧义按'最简单、能跑通'处理"）。
   本项目：`SPEC.md` 里所有子命令、参数、JSON 字段、退出码都由 SPEC 定义；代码与 SPEC 不一致必须改代码，改不了就记 `docs/deviations.md`。

2. **偏离要编号，写清"偏了什么、为什么、替代做法是什么"，只写"不一致"没有价值。**
   出处：`docs/deviations.md` 第 2 条（WAHA 配置只在变了时才 PUT，附指纹做法）、第 7 条（价格数字核对口径的 4 个细则）。
   本项目：`docs/deviations.md` 每条都写"规格原文 → 实际做法 → 原因"，并能对应到一个测试。

3. **错误响应统一结构：可读中文信息 + 机器码，HTTP 状态码与机器码一一对应。**
   出处：`SPEC.md` 第 56 行（`{"error": "<中文可读信息>", "code": "<机器码>"}`）；`docs/deviations.md` 第 6 条把规格没定的错误码补成完整清单。
   本项目：CLI 的 `ErrorInfo` 统一为 `{message, code}`，人类可读一行输出到 stderr，JSON 模式输出到 stdout；退出码映射固定。

4. **密钥永不回传、永不进日志，只能显示"已设置"或后四位。**
   出处：`SPEC.md` 第 51 行（"任何接口都不回传明文"）、第 100 行（"传新值即替换……密钥只记'已修改'"）。
   本项目：行情接口若需要 token，只存 keychain/环境变量，日志与 `--verbose` 都不打印；`config show` 打码。

5. **环境变量统一项目前缀，并且明确禁止读取通用名变量。**
   出处：`SPEC.md` 第 33 行（"只能读带 `INKDOVE_` 前缀的；**禁止读取** `LLM_API_KEY`、`OPENAI_API_KEY`"）、`server/test/auth.test.js` 第 21–31 行有对应断言。
   本项目：只认 `REBAL_` 前缀，测试里断言 `OPENAI_API_KEY` 之类不起作用。

6. **非法配置拒绝启动并说明原因，而不是带着错值跑。**
   出处：`server/test/auth.test.js` 第 11–19 行（密码少于 12 字符、邮箱格式不对、缺 secret 全部 `throws`，错误信息里带变量名）。
   本项目：`config load` 校验失败时列出全部问题（一次报全，不是遇到第一个就停），退出码 2，错误信息里指明变量名和期望格式。

7. **外部服务全部有确定性 mock，一个开关切换；测试和演示都跑在 mock 上，不联网、不花钱。**
   出处：`SPEC.md` 第 49 行（`INKDOVE_LLM_MOCK`）、第 345 行（mock 的行为规则）；`docs/development.md` 第 37 行。
   本项目：`REBAL_QUOTE_PROVIDER=mock` 时从 `test/fixtures/` 的固定报价表返回，价格、日期、货币完全确定。

8. **测试辅助统一一处：临时数据目录、注入时钟、注入等待时间、假外部服务。**
   出处：`server/test/helpers.js` 第 33–90 行（`startApp` 用 `mkdtemp` 建临时目录、把 `mockDelayMs`、`notifyRetryDelayMs`、`wahaPollMs`、`historyImportDelayMs` 等全部注入成 0 或小值）。
   本项目：`test/helpers.js` 提供 `withTempHome()`、`fixedClock()`、`fakeQuotes()`；所有等待参数（重试退避、缓存 TTL）都能注入。

9. **测试里不用固定时长的 sleep 等结果，等"条件成立"。**
   出处：`server/test/helpers.js` 里的 `waitDecided`、`sleep` 只用于轮询间隔；`abuse.test.js` 用 `waitDecided` 等到判定落库。
   本项目：测试等待用 `waitFor(predicate)` 轮询，超时 2 秒即失败，失败信息带最后一次观察到的值。

10. **时序问题是测试失败的首要根因，要修根因，不加重试。**
    出处：`git log` 第 1 条"修复 Telegram 换号主测试的时序问题"；第 60 行附近"文件删除测试等异步删完再查"。
    本项目：涉及文件写入/缓存的用例，一律等条件成立；连续跑 3 遍必须全绿。

11. **每个功能一个提交，提交说明用中文写"用户看得到的行为变化 + 关键数字"，不是"更新代码"。**
    出处：`git log` 前 60 条，例如"看板加「平均回复时间」和按业务员筛选：……20 万条消息 30 天约 0.3 秒"、"推荐回复：改动比例 ≤0.1 直接用、<0.75 改了再发"。
    本项目：提交第一行是行为变化；正文用列表写具体数字（阈值、上限、秒数）和受影响的命令。

12. **文档分层：README 讲价值与安装，features 讲完整行为与实现约定，development 讲结构与测试，external-apis 记核实结果。**
    出处：`README.md` 第 199–209 行（文档索引）、`docs/development.md` 第 5–16 行（各文档职责）。
    本项目：README / `docs/features.md` / `docs/development.md` / `docs/external-apis.md` / `docs/deviations.md` 五份，各自只讲一件事。

13. **外部接口写代码前先核实文档或源码，附链接；实测过的记日期、版本、结果，没核实的标注"没核实"。**
    出处：`docs/external-apis.md` 第 23 行（"10-12 实测，GOWS 2026.9.2……"）、第 35 行（"按文档写的，还没在真机上核实"）、第 37 行（"只读查看，没在真机上调过"）。
    本项目：行情和汇率接口都要在 `docs/external-apis.md` 记"核实方式 + 实测日期 + 返回样例"，没实测的不写进代码。

14. **界面规范先写"要去掉的东西"（至少 10 条 AI 界面通病），再写 token；页面 CSS 不许写死颜色和字号。**
    出处：`DESIGN.md` 第 5–18 行（9 条"要去掉的东西"）、第 20–24 行（"页面 css 里禁止重新定义颜色、字号、圆角、阴影"）。
    本项目：本项目是 CLI，没有 GUI；这条转化为"终端输出规范"：不用 emoji 装饰、不用彩色图标、不用无信息量的标题句、颜色只在状态上（见 `DESIGN.md`）。

15. **不用系统默认控件的默认外观；深色模式跟随系统，不做手动开关。**
    出处：`DESIGN.md` 第 30–34 行（下拉框自绘、滚动条统一、禁用原生 `<select>`）。
    本项目：CLI 不做交互式 TUI；表格列宽按终端宽度计算，宽度 < 60 时降级为逐条列表（对应"375px 也要能用"的思路）。

16. **README 必须如实写风险与局限，并给"适用于 / 不适用于"各 3 条以上。**
    出处：`README.md` 第 28–47 行（"使用前须知"写封号风险、"不适用于"写群发/AI 全自动/单号个人使用）。
    本项目：写清"不做投资建议""行情可能延迟或缺失""不自动下单"等局限。

17. **发版流程固化成 CI：标签与版本号一致 → 跑测试 → 构建 → 建 Release。**
    出处：`docs/development.md` 第 47–53 行；`.github/workflows/release.yml`。
    本项目：`vX.Y.Z` 标签触发同样的四步；版本号只在 `package.json` 一处。

18. **测试文件按功能切分，`describe` 用中文场景名，`it` 用中文断言句；失败时能看出是哪条行为。**
    出处：`server/test/abuse.test.js` 第 8 行起（`describe('防滥用与红线（/api/kb/ask，同一个引擎）')`、`it('注入样本：判为 offtopic，不回复')`）。
    本项目：`test/plan.test.js`、`test/config.test.js`……每个 `it` 都是 SPEC 里的一条可验收行为。

19. **规格里的每条测试要求都能对上用例，覆盖失败路径：401/403/404/409/429/502、格式不对、并发冲突、重启后状态。**
    出处：`SPEC-phase2.md` 第 744–789 行（"每一项都要有 node:test 覆盖……至少覆盖"，逐条列到 F1–F12）。
    本项目：`SPEC.md` 第 9 节逐条列用例，最后用 `docs/features.md` 的"测试对照"回链。
