## 运行中观察到的问题

这 15 次运行暴露出 2 个真问题、2 个「规格如此但读起来怪」的地方：

### 真问题

1. **`执行后` 那行用类别 ID，而不是表里显示的类别名。**
   `1.2` 和 `2` 的表里显示「美股 / A股 / 债券」，下一行却是
   `执行后 us_equity -8.4pp · cn_equity -6.3pp · bond +14.1pp`。
   同一屏里两个名字对不上，新用户会以为 `us_equity` 是别的什么东西。
   → 已修：统一走 `label`（没有 `name` 时回退 ID），回归 T50。

2. **没有 `name` 的资产，「名称」列是一整列空白。**
   `9.2` 的配置没写 `assets.*.name`，表里「名称」列是空白，看起来像解析失败。
   表格的整列占位符过滤只认 `—`，不认空字符串。
   → 已修：空字符串渲染成 `—`，整列都是 `—` 时整列不显示，回归 T51。

### 规格如此、但值得改的措辞

3. **`prices` 里「示例数据（缓存）」有歧义。** （`3`）
   mock 数据的 `fetchedAt` 固定为 2026-01-01，按 TTL 判定必然过期，所以标「缓存」符合
   SPEC §5.10「状态词只有新/缓存」。但示例数据本来就是内置的，读者会以为要 `--refresh`。
   → 不改行为；`docs/features.md` 里说明白「示例数据的时间是固定的，所以总显示缓存」。

4. **空政策时手续费是 0，且没有任何提示。** （`9.2`）
   SPEC §2.2 明确 `fees.per_order` 默认 0，所以这是规格行为，不是 bug。
   但真实券商有佣金，0 手续费算出来的订单金额会偏乐观。
   → 不改默认值（改了就违背契约）；在 `docs/features.md` 的「已知取舍」里写明。

另有两处不是缺陷但值得记录：

- `8.1` 的「卖出 BND 5 股」被正确截断（`债券 的持股不够卖到目标，已把能卖的卖完`），
  这是 SPEC §5.6 要求的行为，工作正常。
- `10.1` 的 TOML 报错把 smol-toml 的英文原文（`illegal character in key` + 带脱字符的行）
  直接透传了。可接受（精确定位比中文意译有用），但可以再补一句中文。
